REPLIT AGENT PROMPT — VELOCITY LAYER + STUCK PROJECTS & TURNAROUND PAGES + OVERVIEW HUB
=======================================================================================
Add a true VELOCITY layer (pace, pace-based ETA, trend) and reorganise the front end so:
- a new "Turnaround" page holds the turnaround-time deep dive,
- a new "Stuck Projects" page holds velocity / stalled / slow-moving work,
- the Overview becomes a SNAPSHOT hub that shows small summaries of both and links to them.
Build on the existing engine (PROCESS_SEQUENCE, cumulative targets, ageing =
today - last_production_date, pre-warning/breach status, change-log between uploads).
Deterministic engine authoritative; AI advisory only. Do not change parsing, Activity
values, dedup, or the alert/threshold math.

====================================================================
A. VELOCITY ENGINE (deterministic, from upload-to-upload history)
====================================================================
Velocity needs MULTIPLE snapshots over time (the change-log/import history). Compute from
the stored snapshots; degrade gracefully when history is thin (see "cold start").

Per MARK (keyed by mark_id, tracked across snapshots):
  - stage_index = position of current Activity in PROCESS_SEQUENCE.
  - movement events = changes in stage_index and/or last_production_date across snapshots.
  - days_per_stage (pace) = (days observed for this mark across history) /
        (net stages advanced over that window). If 0 stages advanced -> pace = infinite/
        "not moving".
  - stages_remaining = (index of Y) - current stage_index   (within its Operation route if
        the route is shorter than full sequence, use the route's remaining steps).
  - ETA (pace-based) = today + days_per_stage * stages_remaining.
        If the mark isn't moving (no advance in the window) -> ETA = "unknown / stalled".
  - TREND = compare recent pace (last 2-3 snapshots) vs earlier pace:
        accelerating / steady / decelerating (or "stalled").
  - velocity_status:
        MOVING (advancing at/around expected pace),
        SLOW (moving but slower than its target pace),
        STALLED (no movement for >= stalled-days, configurable — reuse existing setting).

Target pace (for SLOW/ahead comparison):
  - expected_days_per_stage(activity-window) derived from the Ideal-days settings
    (resolved per project). A mark is SLOW if its observed days_per_stage materially
    exceeds the expected pace for the stages it has been in.

Per CONTRACTOR (and optionally per STAGE/activity):
  - avg_days_per_stage across that contractor's marks (median + mean), and per activity
    (e.g. how long Quality typically holds work for this contractor).
  - throughput = stages advanced per week (or marks completed/week) across recent
    snapshots.
  - Rank slowest contractors / slowest stages by avg_days_per_stage.

Per PROJECT:
  - project velocity = aggregate throughput (stages advanced/week, weight cleared/week),
    avg days_per_stage, and a count of its marks by velocity_status.
  - "Stuck score" = share of the project's weight that is STALLED or SLOW (and/or in
    breach). Use this to rank projects on the Stuck Projects page.

COLD START / DATA SUFFICIENCY
  - With < 2 usable snapshots for a mark: velocity = "insufficient history"; show ageing/
    stalled info only, no ETA. Don't fabricate pace.
  - Clearly label velocity figures with the window used (e.g. "over last 3 reports").
  - All velocity is computed deterministically in the engine; AI may comment, never set it.

ETA vs TARGET (the actionable bit)
  - target_completion = today + (cumulative_target(Y) - ageing)  [budget-based finish].
  - eta_gap = ETA(pace-based) - target_completion.
        eta_gap <= 0  -> on pace to finish on time,
        eta_gap > 0   -> projected LATE by eta_gap days (flag).
  - Stalled marks -> "won't finish on current pace" (treat as high-priority late).

C. NEW PAGE — "Stuck Projects" (velocity / stalled / slow movement)
====================================================================
  - PROJECT LEADERBOARD ranked by "stuck score" (most stuck first): project, stuck weight,
    % of weight stalled/slow, avg days_per_stage, throughput/week, trend arrow.
  - Drill into a project -> its STALLED and SLOW marks: mark, structure, activity, ageing,
    days since last movement, observed pace, pace-based ETA, eta_gap (projected late by),
    contractor, trend.
  - CONTRACTOR view: slowest contractors by avg days_per_stage and by stalled weight.
  - STAGE view: which activities hold work longest (avg days_per_stage), where flow stalls.
  - Filters apply. A "stalled" badge + trend (accelerating/steady/decelerating/stalled)
    on each row. This is the corrective-action worklist for movement (complements the
    Turnaround page which is about time-vs-target).
