## Why the last fix missed this

The earlier search was for the literal string `"Unknown"`. The Activity Wise page uses
`"Unassigned"` for the same thing, so it was never touched. There may be further variants
(`"Not set"`, `"N/A"`, `"Other"`, `"-"`, or an empty string rendered as a dash).

**The search has to be semantic, not textual:** find every place that groups or labels rows
by activity and has a fallback branch for a blank, null or undefined activity — regardless
of which word that branch produces.

## What to check in the reply

- **That the list is longer than one entry.** If it comes back with only Activity Wise,
  push back — the previous textual grep found eleven `"Unknown"` sites across four files,
  so the semantic search should surface a comparable spread.
- **That the logic was extracted into one shared helper**, not copy-pasted a fifth time.
  The condition now exists at four sites after the last change; adding more copies is
  exactly the "same rule in several places" pattern that has caused repeated regressions
  in this codebase.
- **That per-nature checking was preserved.** Any new site using `PROCESS_SEQUENCE` alone
  will flag valid NTLT codes (`NTF`, `NTFSW`, `BL`) as unrecognised — that regression was
  just fixed once and can easily be reintroduced.
- **A real answer to item 4**, with a row count. "Nothing is excluded" is not consistent
  with the 330.258 MT gap.
