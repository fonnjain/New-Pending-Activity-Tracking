# Replit Prompt — Fix the NTLT regression in the activity bucket split
### Follow-up to the "Unknown" rename

The rename work was good and the `||` correction was right. But the new
`Unrecognised activity` bucket uses `PROCESS_SEQUENCE`, which is the **TLT** activity
sequence. NTLT uses three codes that are not in it, so valid NTLT work is now flagged as an
error.

Measured on `WIP_29-07-2026.xls`:

| | Finished Goods (FG) | Known codes | Unrecognised activity |
|---|---|---|---|
| TLT | 8,577 marks / 2,232.207 MT | 50,267 / 8,538.563 | **0 / 0.000** |
| NTLT | 32 / 630.910 | 179 / 2,168.829 | **98 / 3,759.399** |

The three codes falling through: `NTF` (93 marks, 3,729.406 MT), `NTFSW` (4 marks,
29.494 MT), `BL` (1 mark, 0.500 MT).

That is **55% of NTLT's total balance** flagged as an error. The old code handled these
correctly — `NTF` is truthy, so it displayed as its own row.

---

Please make three changes:

## What to check in the reply

- **That it tested all three Order Type settings.** The original fix reported "zero
  unrecognised activities" on the 29-Jul file, which was true only under the default TLT
  filter. That is how this slipped through.
- **That `PROCESS_SEQUENCE` itself was not widened.** It drives TLT stage ordering; adding
  NTF or BL to it would put NTLT codes into the TLT sequence.
- **The answer on the three `reports.tsx` line numbers.** If they belong to another report,
  that report needs the same per-nature fix.
