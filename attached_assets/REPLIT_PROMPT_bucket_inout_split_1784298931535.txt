TASK: Fix the double-counting in the Bucket List In-House / Out-Vendor split. A structure whose
WIP marks span BOTH sides currently has its FULL Order-Review weight placed on BOTH sides, so
the two side-totals overlap and cannot be summed. Replace this with a hybrid split that
reconciles exactly.

=====================================================================
THE BUG
=====================================================================
- Side (in-house / out-vendor) is a WIP property, per MARK (from the mark's Contractor).
- Bucket weights (Release Balance, Fabrication, Galvanising, Yard) are Order-Review properties,
  per STRUCTURE. Order Review has NO concept of in-house / out-vendor.
- 468 of 729 structures (64%) have marks on BOTH sides. Today the app puts each structure's
  full Order-Review weight on BOTH sides -> the same weight is counted twice.
  Symptom: identical numbers appear under In-House and Out-Vendor for the same project (e.g.
  926 shows Rel.Bal 7.587 / Fab+Galva 27.560 / Yard 3.064 on BOTH sides), and the In-House
  total (~8,692 MT) and Out-Vendor total (~7,961 MT) overlap so they must not be added.

=====================================================================
COLUMN SOURCES (Order Review, per structure, BOM-summed)
=====================================================================
  Release Balance = Col S (Balance Release)
  Fabrication     = Col T (Balance Fabrication)
  Galvanising     = Col U (Balance Galvanising)
  Yard            = Col N (Progress Galvanising)
(Join Order Review Col C "Tower Type" == WIP Col J "Alias". NEVER join on WIP Col H.)

=====================================================================
WHY A HYBRID SPLIT (verified research)
=====================================================================
- RELEASE BALANCE has no side: the marks that carry it are "Job Card Not Started + Initial",
  and 100% of them have a BLANK contractor (2,080.763 MT, all blank). Steel that has not been
  released has not been allocated to any fabricator yet — it physically sits in-house.
  DECISION: put ALL Release Balance on the IN-HOUSE side. Do not ratio it.
- FAB / GALVA / YARD cannot be reproduced from WIP (WIP's per-mark balance does not decompose
  into these Order-Review stage buckets; Yard/Progress is cumulative-done and exceeds total WIP
  balance). So keep the Order-Review value and SPLIT it by a WIP-derived side ratio.
- The ratio must come from ALL of a structure's WIP marks (total balance weight per side), NOT
  from stage-specific marks. Stage subsets are tiny and unstable (117 structures have <=2
  galvanising marks -> a stage ratio would be 100/0 or 50/50 noise). The all-marks ratio is
  always defined (every bucket structure has WIP marks — completed ones are already excluded)
  and is a stabler estimate of the structure's in/out work distribution.

=====================================================================
THE SPLIT RULE
=====================================================================
For each bucket structure (after excluding completed / no-WIP structures):

  1) Compute the structure's IN-HOUSE ratio from its WIP marks:
        inWt  = sum of WIP Balance Wt (Col Q) of the structure's marks whose Contractor is
                IN-HOUSE
        outWt = sum of WIP Balance Wt of its marks whose Contractor is OUT-VENDOR
        r_in  = inWt / (inWt + outWt)      [if inWt+outWt == 0, treat r_in = 1.0]
     Side classification of a mark's Contractor (existing rule — keep as-is):
        IN-HOUSE  = CNC*, UNIT-I, UNIT-II, DUMMY CONTRACTOR, NO CONTRACTOR, blank
        OUT-VENDOR = named external vendors, incl. DASHMESH ENTERPRISES GP-2, OUT FAB,
                     S.R.BROTHERS
     (A structure all on one side -> r_in is 1.0 or 0.0 -> whole weight to that side, as
      already decided.)

  2) Release Balance (Col S): 100% to IN-HOUSE. out = 0.

  3) Fabrication (Col T), Galvanising (Col U), Yard (Col N): split by r_in.
        in  = value * r_in
        out = value * (1 - r_in)

The In-House column and Out-Vendor column now PARTITION each structure's weight (no overlap),
so the two sides can be summed to the bucket total.
