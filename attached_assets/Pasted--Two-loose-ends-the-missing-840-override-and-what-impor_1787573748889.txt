## PART 1 — project 840 is missing from the override record

You reported the override metadata on Order Review #66 as **775, 896 and VS-189**, all with reason
`shourt close`, and noted that 840 is absent.

The three short-closed projects make sense together. **840 does not belong with them.** It is a
different event:

```
775 · 896 · VS-189    all five cumulative columns to zero, structure list replaced
                      -> short close. VTPL confirmed 775 was cancelled by the
                         client with material reallocated

840                   still fully present with every structure intact
                      WO Order Qty       370.608 -> 357.143   -13.465
                      Progress Despatch  271.432 -> 261.205   -10.227
                      -> the ORDER ITSELF shrank and every stage followed it.
                         A scope reduction, not a close
```

So either 840 blocked and was not persisted, or it did not block at all. Please run:

```sql
SELECT project_code, columns_affected, stored_value, incoming_value,
       signature, action_taken, status
  FROM anomaly_register
 WHERE seen_on >= '2026-08-24'
 ORDER BY project_code;
```

and report the staging output for the 24-August Order Review — the full block list as the panel
showed it, not only what was persisted.

**If 840 did not block**, that is a rule gap. Its despatch fell 271.432 → 261.205 MT, a plain
cumulative decrease well outside the 0.001 MT tolerance, and the five-column rule should catch it.
Find out why it did not and report before changing anything.

**If it blocked but was not recorded**, the override persistence is dropping entries and the
register will inherit the gap. That matters more than the single project — an audit record that
silently omits one of four is worse than none, because it looks complete.

### While the entries are being touched

- Once 840's entry is found or created, its reason should say **scope reduction**, not short close.
