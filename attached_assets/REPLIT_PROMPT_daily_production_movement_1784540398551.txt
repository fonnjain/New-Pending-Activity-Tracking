PROBLEM — the C row is permanently blank
=====================================================================
Daily Production Movement currently plots each activity by Last Production Entry Date (Col V).
Cutting can never appear: VERIFIED on WIP 20-Jul, 0 of 24,423 C marks have a Last Production
Entry Date, while every other activity has 100% coverage. This is by design — cutting records
progress via Assign Date, not a production entry.

Do NOT "fix" this by plotting C from Assign Date. Assign Date is when material was ASSIGNED
INTO cutting — that is INTAKE, not output — and putting intake in a column headed "Production
Movement" alongside genuine output for other activities would be misleading.

=====================================================================
CHANGE 1 — Cutting row = balance delta between consecutive imports
=====================================================================
Real cutting production shows up as CUTTING BALANCE WEIGHT BEING REDUCED between snapshots.
Nothing flows into C from an earlier stage (it is the first stage), so its reduction is
genuine output.

*** COMPUTE IT AT MARK LEVEL, NOT AS AN AGGREGATE DIFFERENCE. ***
An aggregate delta badly understates output, because newly released work entering C masks the
work leaving it. VERIFIED 19-Jul -> 20-Jul:
    marks that LEFT C entirely          456 marks   106.632 MT   <- finished cutting
    marks still in C with weight DOWN    47 marks    22.003 MT   <- partial progress
    ------------------------------------------------------------
    TRUE CUTTING OUTPUT                             128.635 MT
    marks that ENTERED C (new release)  332 marks    14.709 MT   <- intake, excluded
    NET aggregate change                            -84.317 MT   <- what a naive delta shows
A simple aggregate would report 84.317 MT against a true 128.635 MT — a third of production
lost.

ALGORITHM (per pair of consecutive imports, previous -> current):
    Key each mark by (normalized project Col B, structure Col J Alias, Mark No Col K).
    Consider only marks whose activity was "C" in the PREVIOUS snapshot.
      outputA = sum of previous Balance Wt for marks that are NO LONGER in C in the current
                snapshot (they moved on, or left WIP entirely = fully produced)
      outputB = sum of (previous Balance Wt - current Balance Wt) for marks still in C whose
                weight DECREASED
      Cutting output for that day = outputA + outputB
    EXCLUDE marks that entered C (not present in the previous snapshot) and any weight
    increases — those are intake/corrections, not production.
Scope TLT (Order Nature Col C = "Structure"), using each row's own project code (no forward
fill). Weights are KG in Col Q — divide by 1000 for MT.

Label the C row so its basis is clear (e.g. "C (from balance reduction)") and keep a tooltip
explaining that cutting has no production-date stamp, so output is measured as balance drawdown
between imports.

CHANGE 3 — New second view: NET BALANCE MOVEMENT (bottleneck view)
=====================================================================
Add a second panel/tab beneath (or beside) Daily Production Movement, showing the NET change
in balance weight per activity between consecutive imports:

    net change for activity A on day N = balance(A, day N) - balance(A, day N-1)

Present as a table (rows = activity, columns = the last N days, plus a total) and/or a small
trend chart. Positive = material accumulating at that stage; negative = clearing.

Explain the semantics on screen, because this is the point of the view:
    net change = (work arriving from the previous stage) - (work leaving to the next stage)
A rising figure means work is piling up at that activity — a bottleneck signal. Only Cutting is
unambiguous (nothing feeds into it), which is why Cutting output is measured separately in
Change 1.
