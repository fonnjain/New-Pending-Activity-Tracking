REPLIT AGENT PROMPT — COMPUTED FG (Finished Goods) TAB ON DATA PAGE (separate field, no auto-populate elsewhere)
===============================================================================================================
Add a "FG (Finished Goods)" tab on the Data page that shows Finished Goods computed per
project + structure, for TLT and NTLT. Store the result in a NEW separate field "computed_fg"
— do NOT populate the existing blank "fg" placeholder or change anything else in the app.
Deterministic computation + a display tab; do not change WIP parsing, ageing, dedup, warnings,
completion, or dispatch logic.

THE FORMULA (per project + structure, weight in MT)
    Computed FG = Release − (All Activities Balance Weight) − Dispatch
  Where:
    - Release (MT)  = Order Review file, Progress > Release (Col L) for that project+structure.
    - Dispatch (MT) = Order Review file, Progress > Despatch (Col Q) for that project+structure.
    - All Activities Balance Weight (MT) = sum of Balance Wt (÷1000) of that project+structure's
      marks currently sitting in ANY activity in the WIP data (the mark-level pending work).
        * TLT activities: C, HG, RFI, NH, B, HAB, W, Q, TS, G, GB, Y (all the TLT stages).
        * NTLT activities: the NTLT stages (RSJ: NTF, NTFSW, NTFW, TS, G, GB, Y; Earthing/
          General: TS, G, GB, Y). Use each row's own category activity set.
      i.e. it's simply the total remaining balance weight of that structure's marks in the WIP
      file (every mark still present is in some activity), grouped by project+structure.
  MEANING: of what was released into production, subtract what is still moving through the
  activities (WIP) and what has already been dispatched — the remainder is finished goods on
  hand (finished, not yet dispatched).

  NOTES / DATA HANDLING
    - Base is Release (what entered production), NOT Order Qty and NOT WO Order Qty. (WO Order
      Qty is only for the balance equations, not for FG.)
    - Blank Release/Dispatch -> treat as 0.
    - Small negative results (rounding/timing noise between the same-day WIP and Order Review
      files, typically < ~1 MT) -> clamp to 0 for display AND flag the row as a minor anomaly.
      Materially negative (e.g. < −1 MT) -> flag prominently for review (don't hide).
    - Round to 3 decimals (MT).
