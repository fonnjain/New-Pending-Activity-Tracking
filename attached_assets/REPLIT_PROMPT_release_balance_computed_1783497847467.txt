TASK: Add a WIP-derived "Release Balance Computed" metric and a new "Release Balance" tab
on the Data page that shows it alongside the existing Order-Review Release Balance.

=====================================================================
CONTEXT / ERP SEMANTICS (verified against the WIP file)
=====================================================================
The WIP export's Column A ("Type") has exactly three values:
   1. "Job Card Not Started"
   2. "Job Card WIP"
   3. "FG Pending For Dispatch"

Within "Job Card Not Started", Column G ("Job Card Status") is either "Initial" or
"Authorized", giving three real-world states:
   - Not Started + Initial              → factory has NO steel; steel release is PENDING.
                                          Contractor (Col D) is ALWAYS BLANK here.
                                          (Verified: 0 of these rows have a contractor.)
   - Not Started + Authorized + Col D has a contractor name
                                          → job card assigned to a contractor, but
                                            Cutting (C) not yet started.
   - Not Started + Authorized + Col D BLANK
                                          → job card not assigned to anyone = "Assignment
                                            Balance".
"Job Card WIP" rows carry operations/activities from RFI..Y (varies per card) and NEVER
include Cutting (C). (Verified: 0 WIP rows have Activity = C.)

WIP column map (header on row 4; 24 columns). Relevant columns:
   A=Type, B=Project Code, C=Order Nature, D=Contractor, G=Job Card Status,
   J=Alias(=structure), Q=Balance Wt., S=Activity.
Project Code is forward-filled: it appears on "Structure" rows (Col C = "Structure").

IMPORTANT UNIT FACT: WIP Col Q "Balance Wt." is in KILOGRAMS. The existing Order Review
Release Balance (Col S of Order Review) is in TONNES (MT). All comparisons below convert
the WIP value to MT by dividing by 1000.

=====================================================================
NEW METRIC: "Release Balance Computed"  (WIP-derived; SEPARATE from existing)
=====================================================================
Definition:
   Release Balance Computed (MT) = SUM( WIP Col Q ) / 1000
   over rows where  Col A == "Job Card Not Started"  AND  Col G == "Initial".
   Group by (normalized project, structure=Alias).

This is a NEW, independent field. It is NOT the existing Release Balance. The existing
Release Balance (from the Order Review file, Col S) MUST remain completely untouched
everywhere in the app — do not repurpose, rename, or recompute it. Two different numbers,
both retained.

Add it additively to the WIP-derived data (e.g. a computed column/aggregate keyed by
project+structure). Do NOT alter parsing, hashing, dedup, ageing, Activity, or qty. Use the
EXISTING project-code normalizer (strip trailing "."/".0"); do not add a new one.

Verified magnitudes on the current files (for the ACCEPTANCE CHECK — will move with new
uploads):
   - Release Balance Computed grand total ≈ 2387.061 MT over 240 (project,structure) keys,
     summed over 10,045 "Not Started + Initial" rows (raw Col Q ≈ 2,459,405.877 kg).
   - Type counts: Job Card WIP ≈ 28,477; Job Card Not Started ≈ 26,131 (Initial ≈ 10,045,
     Authorized ≈ 16,086); FG Pending For Dispatch ≈ 5,167.
   - Of Authorized-not-started: ≈ 11,518 have a contractor; ≈ 4,568 are blank (Assignment
     Balance). These are informational — the metric itself is Initial-only.
