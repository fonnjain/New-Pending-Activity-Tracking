## PART 1 — follow-up #66: preserve the panel and override evidence

Please go ahead with this. It closes the gap that made today's investigation necessary.

The whole audit problem this week was that **the staging panel's findings did not survive a
delete-and-re-import cycle**. #65 was committed from the 24-August file, then deleted, and its
override details went with it. #66 was committed later and retained only three of the four
blockers. You had to reconstruct the original four-project panel from retained source bytes to
answer whether 840 had blocked.

That reconstruction was well done, but it should never need doing again.

### What to store

At **stage time**, before any import decision is made, persist the panel's findings independently
of the import record — so that deleting an import cannot remove the evidence of what it showed:

```
staged_at              timestamp
source_filename
source_hash            so the panel can be tied back to exact file bytes
kind                   wip | order_review
compared_against       the import id used as the baseline
blockers               jsonb   the full panel output, per project:
                               signature · columns moved with both values ·
                               columns that did not move · structure detail ·
                               upward movements
warnings               jsonb   absent projects, with despatch history and
                               outstanding weight
outcome                imported | skipped | refused
import_id              null when skipped or refused
```

Two properties matter more than the schema:

**It must survive deletion of the import.** That is the entire point. If an import is deleted, its
staging record stays.

**It must be written even when the file is never imported.** A refused or skipped file is exactly
the case where the evidence is most likely to be wanted later, and exactly the case where nothing
is recorded today.

Link it to the anomaly register where the two describe the same event, so an open register entry
can be traced back to the panel that raised it.

### Backfill what is known

You already reconstructed the 23-August against 24-August panel deterministically. Store that
reconstruction as a staging record, clearly marked as a reconstruction rather than a live capture,
so the four-project block list is durable rather than living in a chat transcript.
