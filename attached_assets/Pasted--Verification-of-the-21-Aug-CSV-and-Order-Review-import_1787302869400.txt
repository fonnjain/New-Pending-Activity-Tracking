# Verification of the 21-Aug CSV and Order Review imports

The 21-Aug WIP CSV and Order Review have been uploaded. Below are the figures computed directly
from those two files, before the app touched them. Please compare the app's output against every
one and report each individually — not a summary.

**State which database each query ran against.** Dev and production have diverged repeatedly in
this project and it has caused wrong conclusions more than once.

---

## FIRST — the format changed again

The 21-Aug CSV has **36 columns**. The 20-Aug CSV had 28, and the file before that had 26. Eight
new columns appeared in a single day:

```
Lot Document No.        Lot Document Date       Lot Source Form         Issue Lot Rate
Issue Document No.      Issue Document Date     SinRateForIssueMonth    NearestSinDateToIssue
```

The first 28 are unchanged in name and order. Everything new is appended.

**Do not treat the column count as fixed.** The parser resolves by header name, which is why this
keeps working — that behaviour must be preserved. But the "known columns" list needs these eight
added, or the staging panel will warn on every upload from here and people will learn to click
past it.

**Do not build any logic on the new columns yet.** Store them, surface them in the Source Column
Watch panel, and nothing else. See the closing note for why they matter later.

## CLOSING NOTE — what the eight new columns actually are

Worth understanding before deciding what to do with them, because they are not routine.

They are **material issue and cost data**, populated on 67.5% of rows — specifically on
`Job Card WIP` (28,050 of 29,713) and `FG Pending` (22,729 of 23,110), and on **none** of the
22,431 `Job Card Not Started` rows. That pattern is coherent: material is issued when work starts.

```
Lot Source Form   Material Return 22,735 · SIN Lot Entry 22,530 · SIN Entry 4,800
                  RM Stock Transfer 664 · RawMaterial Stock Adjustment 40 · CBOM Rejection 10
Issue Lot Rate    50,779 values · min 3.00 · max 88.00 · mean 50.74
```

`Issue Lot Rate` at a mean of 50.74 reads as rupees per kilogram of steel. If that is right, this
is the first cost-per-tonne data the tracker has ever received, and it is exactly what the
material-wastage and finance-cost workstreams were blocked on.

**One data-quality caveat before anyone builds on it.** `SinRateForIssueMonth` looks unit-mixed:
49,929 values fall below 100, but 339 rows carry 1,348 · 46,830 · 52,680 · 69,500 — and on 333
rows that field is more than 100× the `Issue Lot Rate` on the same line. That looks like rupees
per tonne in a few rows where the rest are per kilogram. Worth confirming with the ERP team before
any calculation uses it.

Store and watch for now. Do not compute anything from these columns until VTPL confirms the units
and which of the two rate fields is authoritative.
