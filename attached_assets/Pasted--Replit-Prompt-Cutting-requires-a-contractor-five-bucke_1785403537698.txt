# Replit Prompt — Cutting requires a contractor: five buckets become six
### Assignment Balance changes from a subset of Cutting to a peer bucket

**The change in one line:** Cutting means work actually being cut — a contractor is on it.
Released work with nobody assigned sits in Assignment Balance instead. Nothing is lost;
it moves.

## What to check in the reply

- **The call-site inventory, before any changes.** If it comes back with three or four
  entries, push back. Cutting was previously computed seven different ways, and the copies
  multiplier touched ten files. A short list means the search was textual rather than
  semantic.
- **One shared function, not a copy per site.** If the reply shows the condition written out
  in several files, the same divergence will reappear within weeks.
- **1,414.718 MT / 9,723 marks on every surface.** Any page still reading 2,519.232 is on
  the old definition. This is the single fastest check — one number, every screen.
- **The grand total must move by exactly the TS amount and nothing else.** The Cutting split
  is total-neutral (Assignment + new Cutting = old Cutting), so the only legitimate change
  is −321.158 MT for TS. On the filtered export that takes 6,497.646 to roughly 6,176.5.
  Any other figure means the include/exclude flip landed inconsistently.
- **That Q and TS are genuinely separate columns**, with TS visible but outside the total.
- **That Assignment is now INCLUDED in totals, not excluded.** This is the reversal most
  likely to be applied in only some of the places it needs to be.
- **Zero unclassified under all three Order Type settings.** The six buckets must partition
  the file exactly; any residual means one bucket is still using an old condition.
- **That the 821 assertion was replaced, not deleted.** It remains a useful regression test —
  it has just moved from Cutting to Assignment.

## One thing to decide

Excluding TS from the total means the Fabrication Report's total **no longer equals the sum
of all fabrication-stage work** — 321.158 MT (4.9% of the report) sits in a visible column
that nothing adds up. That is defensible if the intent is "balance still to be fabricated",
since TS work has finished fabrication and is awaiting sign-off.

But it does break the property that made this total easy to verify: it can no longer be
reconciled against any bucket. Worth deciding explicitly whether TS should be dropped from
the report altogether rather than shown-but-uncounted, since a column that is displayed and
excluded invites the same "why doesn't this add up" question the reconciliation warning
used to cause.
