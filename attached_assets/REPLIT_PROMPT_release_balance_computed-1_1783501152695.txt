=====================================================================
CRITICAL ORDER-REVIEW PARSING RULE (Proto / Mass / Pre BOM rows)
=====================================================================
In the Order Review file, a single structure spans MULTIPLE ROWS — one per BOM Label
(Col K): "Proto", "Mass", and/or "Pre". The STRUCTURE CODE (Col C = Tower Type) appears
only on the FIRST row of the structure; the continuation rows (Mass / Pre) have Col C
BLANK and belong to the structure above them. The balance/progress values (Release Col S,
Fabrication Col T, Galvanising Col U, Progress-Galv Col N, Inspection Col O, etc.) are
distributed ACROSS these rows — often the Mass row carries the bulk of the weight.

Therefore, to get a structure's Release Balance (or any S/T/U/N/O value) you MUST SUM the
column across ALL of that structure's BOM rows (the Proto/first row PLUS the following
Mass/Pre continuation rows with blank Col C), grouped under the structure code that carries
down from the first row.

DO NOT take only the first row per structure. A parser that keys on "Col C non-blank" and
ignores continuation rows will DROP the Mass/Pre values and massively under-count. This is
a real, verified bug: for project 920 it produced 0.267 MT instead of the correct
76.511 MT (the file's own Col S subtotal for 920 is 76.509 MT). The error is wildly uneven
per project — some projects sit almost entirely on Mass rows.

VERIFY the app's existing Order Review parser against this rule. If order_review_rows is
already storing one summed value per structure across all BOM rows, good — leave it. If it
is only capturing the first/Proto row, that is a BUG: fix the Order Review aggregation to
sum across BOM rows per structure (additively; do not change identity/hash). Confirm by
checking project 920 reads 76.5 MT, not 0.267 MT.

NEW METRIC: "Release Balance Computed"  (WIP-derived; SEPARATE from existing)
=====================================================================
Definition:
   Release Balance Computed (MT) = SUM( WIP Col Q ) / 1000
   over rows where  Col A == "Job Card Not Started"  AND  Col G == "Initial".
   Group by (normalized project, structure=Alias).

This is a NEW, independent field. It is NOT the existing Release Balance. The existing
Release Balance (from the Order Review file, Col S) keeps its DEFINITION and units — do
not repurpose or rename it. The only allowed change to it is the BOM-summing CORRECTNESS
fix described in the CRITICAL PARSING RULE above (sum across Proto/Mass/Pre rows if the
current parser wrongly uses only the first row). These remain TWO different numbers, both
retained: Order Review Release Balance (Col S) vs WIP Release Balance Computed.

Add it additively to the WIP-derived data (e.g. a computed column/aggregate keyed by
project+structure). Do NOT alter parsing, hashing, dedup, ageing, Activity, or qty. Use the
EXISTING project-code normalizer (strip trailing "."/".0"); do not add a new one.
