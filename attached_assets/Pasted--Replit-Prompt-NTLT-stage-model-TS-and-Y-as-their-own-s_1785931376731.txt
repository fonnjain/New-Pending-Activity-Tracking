## The prompt

```
Please implement a proper NTLT stage model. NTLT currently borrows TLT's stage definitions and
that is wrong — the two natures have different process chains and different activity
vocabularies.

THE NTLT CHAIN

    Not Started  ->  TS  ->  Galvanising (G, GB)  ->  Y  ->  Finished Goods

TS comes BEFORE galvanising. Y comes AFTER. Both are their own stages — do NOT fold TS into a
fabrication bucket and do NOT fold Y into Galvanising.

THE RULES (all require the Type guard — see the warning below)

    Not Started     = Type "Job Card Not Started"                      (any activity)
    TS              = Type "Job Card WIP" AND activity = TS
    Galvanising     = Type "Job Card WIP" AND activity in {G, GB}
    Y               = Type "Job Card WIP" AND activity = Y
    Finished Goods  = Type "FG Pending For Dispatch"                   (activity blank)

THE TYPE GUARD IS NOT OPTIONAL

G and TS appear under BOTH "Job Card Not Started" and "Job Card WIP". On the 05-Aug import
there are 695.194 MT of not-started G and 21.570 MT of not-started TS. Keyed on activity alone
that 717 MT lands in the wrong stage. This is the same failure that inflated Quality Check on
the All view previously — please do not reintroduce it.

VERIFIED FIGURES — this model partitions NTLT exactly with ZERO unclassified marks on three
separate days:

If your implementation produces any unclassified NTLT marks, a rule is wrong.

NOTE THE STAGE COUNTS DIFFER BY NATURE

TLT has six buckets (Release, Awaiting Assignment, Cutting, Quality Check, Galvanising,

The complete NTLT set is: BL, G, GB, NTF, NTFSW, TS, Y — seven codes, matching the existing
NTLT_ACTIVITIES constant. Three points:

Please apply this everywhere NTLT stages are computed — Project Wise, Activity Wise, Plant
Operation Wise, the ERP rules and every Excel export. Use one shared definition, not a copy

When done, paste the stage definitions and give me the five NTLT figures for the latest
import.
```

## What to check in the reply

- **Zero unclassified NTLT marks.** The model is verified to partition exactly; any residual
  means a rule was mistyped.
- **That Y is a separate column, not merged back into Galvanising.** This is the change most
  likely to be quietly undone, since every other view in the app groups `G, GB, Y` together.
- **That the Type guard is on all three WIP-stage rules.** Without it, 717 MT moves to the
  wrong stage and the totals still look plausible.
- **One shared definition.** The same rule copied per page is what produced the recurring
  regressions throughout this project.
