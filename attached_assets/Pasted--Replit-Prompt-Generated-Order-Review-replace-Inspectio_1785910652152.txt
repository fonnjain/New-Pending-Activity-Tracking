```

    Gen Finished Goods (MT)  = WIP rows with Type = "FG Pending For Dispatch", summed per
                               structure
    OR Finished Goods (MT)   = Order Review Progress Galvanising (Col N)
                               minus Progress Despatch (Col Q)

The chain becomes: Release -> Fabrication -> Galvanising -> Finished Goods, gen and OR side
by side at each stage.

EXPECT A LARGE GAP ON THE FG PAIR. THIS IS CORRECT, NOT A BUG.

    Gen FG (WIP)   2,439.518 MT across 397 structures

CHANGE 2 — Keep the format identical

Same column grouping, same gen/OR pairing, same per-project subtotal structure as the current
view. Only the stage set changes. The Excel export must match the UI layout.

CHANGE 3 — The match-rate panel shows 0/0 for every stage

Show matched/total as the label implies, not a bare percentage. The denominators shrink down

has not been briefed, and a difference between them looks like an error.

Please rename so the source is visible in the label: "FG (WIP file)" and "FG (Order Review)"
or similar, wherever each appears.

Confirm that nothing sums the WIP-derived FG and the OR-derived FG into a single total, and
that neither is used as a silent fallback when the other is missing. They measure overlapping

I am asking because FG previously had two representations in this codebase (record_pool rows
and the imports.summary.fgWipByStructure jsonb) with nothing verifying they agreed, and that
only surfaced because it produced a permanent false reconciliation warning.

ALSO — negative OR FG on 6 structures

Six structures compute a negative OR Finished Goods on 04-Aug (Despatch Progress exceeds

inconsistency in the Order Review, not ordinary divergence. Surface these rather than

When done, paste the new column set, and tell me the four match-rate figures the panel
```
