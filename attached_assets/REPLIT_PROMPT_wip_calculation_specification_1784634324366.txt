=====================================================================
THE FIVE COLUMNS THAT DEFINE EVERY CASE
=====================================================================
Read ALL columns by HEADER NAME, never by position (the layout has changed before).

  Col A  "Type"              -> the mark's production STAGE      (3 values)
  Col C  "Order Nature"      -> TLT vs NTLT                      (4 values)
  Col G  "Job Card Status"   -> released or not                  (2 values)
  Col I  "Tower Sub Type"    -> descriptive attribute            (27 values)
  Col L  "Section"           -> material spec / NTLT identity    (217 values)

Verified value sets (WIP 21-Jul, 60,594 rows). These are CLOSED sets — anything else is a
data-format change and must raise a warning, not be silently bucketed:

  Col A: "Job Card Not Started" (26,708) | "Job Card WIP" (26,871) | "FG Pending For Dispatch" (7,015)
  Col C: "Structure" (60,276) | "RSJ POLE" (266) | "EARTHING" (28) | "GENERAL" (24)
  Col G: "Authorized" (49,141) | "Initial" (11,453)

Normalise before comparing: trim whitespace, compare case-insensitively. Do not match on
prefixes or partial strings.

=====================================================================
STEP 1 — TLT / NTLT SPLIT (Col C alone)
=====================================================================
        Col C == "Structure"                     -> TLT
        Col C in {RSJ POLE, EARTHING, GENERAL}   -> NTLT

Col C is the SOLE classifier. Do not infer TLT/NTLT from project code, sub type, section or
activity. Verified: 100% of NTLT rows have a BLANK project code (Col B) and a BLANK Alias
(Col J); 100% of TLT rows have both populated. NTLT therefore cannot join to Order Review and
is keyed by Section (Col L) alone.

All calculations below are TLT unless stated. NEVER forward-fill the project code.

=====================================================================
STEP 2 — THE FOUR CASES (Col A x Col G) — MUTUALLY EXCLUSIVE, EXHAUSTIVE
=====================================================================
Every mark falls into EXACTLY ONE of these four cases. There is no overlap and no fifth case.
This matrix is the whole specification — verified on TLT rows:

  #  Col A "Type"              Col G "Status"   Activity   Marks    Weight (MT)   Meaning
  -- ------------------------- ---------------- ---------- -------- ------------- ----------------------------
  1  Job Card Not Started      Initial          C          11,453    2,538.863    NOT RELEASED (raw material)
  2  Job Card Not Started      Authorized       C          15,137    2,597.052    CUTTING (released, pending)

Structural facts that make these cases unambiguous (all verified):
  - "Job Card Not Started" ALWAYS has Activity = C. No other activity occurs with it (TLT).
  - "Job Card WIP" NEVER has Activity = C. It is always a post-cutting activity.
  - "FG Pending For Dispatch" ALWAYS has a BLANK activity, and is ALWAYS Authorized.
  - "Initial" occurs ONLY with "Job Card Not Started". Cases 3 and 4 are always Authorized.
  => Therefore Col G only ever discriminates WITHIN "Job Card Not Started". Applying a Job
     Card Status filter anywhere else is a no-op at best and a bug at worst.

no gaps. Assert this per project.

STEP 4 — COLUMNS I AND L (attributes, not filters)
=====================================================================
  Col I "Tower Sub Type" (27 values) — a DESCRIPTIVE attribute. Identical to Order Review
        Col D (verified 729/729 agreement). Use for grouping/bifurcation (e.g. Stub / SST /
        Other in the fabrication report). NEVER use it to include or exclude a mark from a
        calculation.

  Col L "Section" (217 values) — the material spec. Its ONLY structural role: it is the
        IDENTITY of NTLT rows, which have no project and no structure. Group NTLT by Section.
        For TLT it is descriptive only. NEVER use it as a calculation filter.

  Neither column may ever appear in a Cutting/Release/FG/activity filter condition.
