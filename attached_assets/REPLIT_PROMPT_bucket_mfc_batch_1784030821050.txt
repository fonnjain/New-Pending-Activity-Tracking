TLT-ONLY IS AUTOMATIC — no filter needed:

=====================================================================
CHANGE 1 — EXCLUDE COMPLETED STRUCTURES from the buckets
=====================================================================
A bucket structure that has NO matching WIP marks is COMPLETE — production is finished, so it
has dropped out of the WIP file (WIP only holds marks with remaining balance).

Evidence: of the 916 no-WIP structures in Bucket D, Released == Inspected == the full Work
Order qty; 91% have zero release balance; 81% are essentially fully dispatched.

RULE: if a (project, structure) from Order Review has NO marks in the latest WIP import
(joined on project + structure==Alias, Order Nature = "Structure"), EXCLUDE it from the bucket
list entirely. It is completed work; the bucket list is for live work.

Counts to expect (current files):

    Bucket C: 1429 -> 487 structures (942 completed excluded)
    Bucket D: 1174 -> 258 structures (916 completed excluded)

Show the excluded count somewhere unobtrusive (e.g. "39 completed structures excluded") so the
user knows they were dropped deliberately, not lost.

=====================================================================
CHANGE 2 — MFC BATCH column
=====================================================================
MFC Batch = WIP Col X "Batch No.". It holds exactly four values: A, B, C, D. It is a per-MARK
field; 53.5% of WIP rows have it BLANK (mostly marks not yet in production).

STRUCTURE -> MFC BATCH assignment (deterministic; verified unambiguous):
    Collect the MFC Batch of all the structure's WIP marks (blank -> treat as "not batched").
      - If ANY mark has a real batch (A/B/C/D) -> the structure's MFC Batch is that batch.
      - If NO mark has a real batch (all blank) -> the structure's MFC Batch is "Z"
        (= Not Yet Batched). This matches the app's existing "blank batch -> Z" convention.
      - EDGE CASE: if a structure somehow has TWO OR MORE real batches, take the one with the
        greatest balance weight. (Verified: only ONE structure in the entire file does this —
        920 / 3LISO with C and D. It is not a practical concern, but handle it deterministically
        rather than crashing.)

    IMPORTANT — Z is NOT a batch, it means "in production but no batch assigned yet". Do not
    confuse it with completed structures (which are now excluded entirely per CHANGE 1). Those
    are different states: Z = live work awaiting batch; completed = gone from WIP.

DISPLAY: add "MFC Batch" as a COLUMN in the tabular data, positioned immediately AFTER the
Project column. Do NOT restructure the table into an MFC hierarchy, and do NOT remove the
existing In-house / Out-vendor split — that stays exactly as it is. MFC Batch is simply an
extra column (values: A, B, C, D, Z), sortable/filterable like the others.
