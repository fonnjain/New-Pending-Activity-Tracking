TASK: Add a "Order Review" tab to the DATA page that shows a GENERATED Order Review, built from
WIP, for NEWLY STARTED projects — the ones that have just begun appearing in WIP as they move
from Bucket A to Bucket B.

=====================================================================
WHY THIS IS POSSIBLE (verified research — read this first)
=====================================================================
Order Review's Progress columns (L/M/N) are CUMULATIVE WORK DONE. WIP only holds REMAINING
balance: once a mark is fully produced it disappears from WIP entirely. So for a MATURE project
WIP can never reconstruct Order Review — the completed history is simply gone.

BUT for a project that has only just started, almost nothing has been produced, so nothing has
dropped out of WIP yet — WIP therefore holds the COMPLETE picture and the Order Review can be
generated from it exactly.

VERIFIED match rate of generated Balance Release vs actual Order Review, by project maturity:
        0-5%  released ->  4 projects, 100% match   <-- the target population
        5-25% released ->  2 projects,  50% match
       25-50% released ->  2 projects,  50% match
       50-90% released ->  7 projects,  71% match
      90-100% released -> 50 projects,  90% match
The reconstruction is only trustworthy at the very start. That is exactly the Bucket A -> B
transition window, which is what this tab is for.

=====================================================================
SCOPE — which projects appear
=====================================================================
Include a project when BOTH are true:
    1) It has WIP marks (Order Nature = "Structure", project = its own Col B).
       This is the "data has started appearing in WIP" trigger — i.e. it has left Bucket A.
    2) Progress Release (Order Review Col L) < 5% of WO Order Qty (Col J).
       This is the trust boundary; beyond it WIP has lost completed work and the generated
       figures would be wrong.
Handle Col J == 0 safely (no divide-by-zero): if a project has WIP marks but no WO qty yet,
include it and treat released % as 0.

Projects still IN Bucket A are NOT shown here: they have no work order and therefore ZERO WIP
marks (verified: 0 of 46), so there is nothing to generate. The tab populates automatically the
moment their marks appear in WIP.

On the 19-Jul files this yields exactly 4 projects:

=====================================================================
GENERATION LOGIC (per project + structure, structure = WIP Col J "Alias")
=====================================================================
Group WIP marks by (project = Col B, structure = Col J Alias), TLT only (Order Nature = Col C
= "Structure"). Then:

  RELEASED / NOT RELEASED split (the core of it):
      notReleased = SUM(Col Q Balance Wt) where Col A "Type" = "Job Card Not Started"
                                            AND Col G "Job Card Status" = "Initial"
      released    = SUM(Col Q Balance Wt) for every OTHER mark of that structure

  Generated columns:
      L  Progress Release      = released
      S  Balance Release       = notReleased
      M  Progress Fabrication  = SUM(Col Q) of marks past fabrication
                                 (Activity in G, GB, Y, or Type = "FG Pending For Dispatch")
      T  Balance Fabrication   = SUM(Col Q) of marks still in fabrication activities
                                 (Activity in C, HG, RFI, NH, B, HAB, W, Q, TS)
      N  Progress Galvanising  = SUM(Col Q) of marks at/after galvanising
                                 (Activity in Y, or Type = "FG Pending For Dispatch")
      U  Balance Galvanising   = SUM(Col Q) of marks not yet galvanised
                                 (Activity in C, HG, RFI, NH, B, HAB, W, Q, TS, G, GB)
      V  Balance Inspection    = SUM(Col Q) of marks not yet inspected
                                 (everything except Type = "FG Pending For Dispatch")

  Also show per structure: Tower Sub Type (WIP Col I), MFC Batch (Col X, blank -> "Z"),
  mark count, and total WIP Balance Wt.

Weights: WIP Col Q is in KG — divide by 1000 and present as MT, 3 dp, consistent with the rest
of the app.
