=====================================================================
GROUPING
=====================================================================
Rows are per (Project/Job code × BOM Label). No structure-wise or mark-wise breakdown —
all measures sum Mark → Structure → Project(×BOM Label).

BOM Label comes from Order Review (Col K: "Proto" / "Mass" / "Pre"). WIP has NO BOM Label
column, so BOM Label is obtained by joining a WIP mark's structure to Order Review on
(normalized project + structure), where structure = WIP Alias (Col J) == Order Review Tower
Type (Col C). Also available for disambiguation: Tower Sub Type = WIP Col I == Order Review
Col D.

MULTI-BOM STRUCTURES: ~95 structures span MORE THAN ONE BOM Label (mostly Proto+Mass). A
WIP balance for such a structure cannot be cleanly attributed to a single BOM Label.
Therefore: any structure whose Order Review rows carry more than one distinct BOM Label is
assigned to a SEPARATE BOM Label bucket called "Mixed". So each project can have up to four
BOM rows: Proto, Mass, Pre, Mixed. A structure with exactly one BOM Label goes to that
label; a structure with 2+ labels goes to "Mixed". (Structures with no Order Review match →
BOM Label "Unknown"; show as its own row, do not drop.)

=====================================================================
COLUMNS (all MT, summed to Project × BOM Label, TLT marks only)
=====================================================================
1. Project / Job code            (normalized; strip trailing "."/".0" with existing normalizer)
2. BOM Label                     (Proto / Mass / Pre / Mixed / Unknown)
3. Release Balance Calculated    = WIP-derived, SAME logic already defined earlier:
       SUM(WIP Col Q)/1000 where Type (Col A) = "Job Card Not Started" AND Job Card Status
       (Col G) = "Initial". (Contractor is always blank on these rows.)
4. Assignment Balance Calculated = SUM(WIP Col Q)/1000 where Type (Col A) = "Job Card Not
       Started" AND Contractor (Col D) is BLANK (no one assigned).
       NOTE ON OVERLAP (intended, do NOT "fix"): a "Not Started + Initial" row also has a
       blank contractor, so it is counted in BOTH Release Balance Calculated AND Assignment
       Balance Calculated. These are two different lenses; overlap is expected.
5. Cutting Balance (C)           = SUM(WIP Col Q)/1000 where Activity (Col S) = "C".
6. Quality Check Balance (RFI to TS) = SUM(WIP Col Q)/1000 where Activity (Col S) ∈
       {RFI, NH, B, HAB, W, Q, TS}  (fabrication ops before galvanizing; same set the
       Project-wise report uses for its Quality Check measure — reuse that definition/const
       if it exists, don't redefine).

WIP relevant columns: A=Type, D=Contractor, G=Job Card Status, I=Tower Sub Type, J=Alias
(=structure), Q=Balance Wt.(kg), S=Activity. Project Code (Col B) is forward-filled from
"Structure" rows (Order Nature Col C = "Structure").
