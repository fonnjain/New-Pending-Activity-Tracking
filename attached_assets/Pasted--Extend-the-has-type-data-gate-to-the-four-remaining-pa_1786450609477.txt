# Extend the `has_type_data` gate to the four remaining pages

You already built this for DC6 in `dataCheck.ts` — read `import_rows.job_card_type` and
`job_card_status` directly, probe whether the import has any non-null type row, and show an
amber N/A card instead of figures when it does not. That was the right shape. Apply the same
pattern to the four pages that still fall back to `record_pool`.

**No re-ingest. No file uploads. No stored value changes.** This is a display gate only.

---

## THE PROBLEM

Imports 5 through 32 were written by the pre-01-Aug ingest code, which never stored `Type`
(Col A) or `Job Card Status` (Col G) in `import_rows`. Every row of those 21 imports has
`job_card_type = NULL`. The queries then do:

```sql
COALESCE(import_rows.job_card_type, record_pool.job_card_type)
```

and fall through to `record_pool` — which the 10-Aug bulk upload has since rewritten. A mark
that was at Cutting on 21-Jul and is at Galvanising today is classified as Galvanising **in the
21-Jul view**. The page assembles a snapshot of a date that never existed.

Measured effect on import 30 (21-Jul):

```
app shows      Release Balance 2,512.230 MT,  369.737 MT unclassified
source file    Release Balance 2,538.863 MT,        0 MT unclassified
```

Import 9 (04-Jul) is the worst case: 22,897 of its 39,305 rows inherit a type this way,
producing 6,087 MT of fabricated classification.

**This is now urgent because DC6 already refuses to evaluate these imports while the pages still
show figures for them.** On the same import, the Data Check tab says "classification data not
available" and Release Balance shows a number. The app contradicts itself.

## A. Extract the probe into one shared helper

Put it next to `loadLatestWipImport()` in `dispatch.ts`, or wherever `dataCheck.ts` currently
holds it — but **one definition, imported everywhere**. We consolidated the activity sets into
`lib/domain` for exactly this reason; do not let a second copy of this appear.

```
hasTypeData(importId) =
  EXISTS (SELECT 1 FROM import_rows
          WHERE import_id = <importId> AND job_card_type IS NOT NULL)
```

If `dataCheck.ts` already has this inline, move it to the shared location and have `dataCheck.ts`
import it too.

## B. Apply it at these four call sites

| File | Sites | Page affected |
|---|---|---|
| `lib/parseWipReleaseBalance.ts` | 3 COALESCE expressions | Release Balance |
| `routes/erpRules.ts` | lines 125, 126, 134 | ERP Rules |
| `routes/fabricationProjectCompletion.ts` | lines 221, 222, 224, plus 3 more | Fabrication Project Completion |
| `routes/productionMovement.ts` | line 299 | Production Movement |

For each: when `hasTypeData` is **false**, return no figures and a reason string. When it is
**true**, leave the query exactly as it is — the COALESCE is correct there, because it handles
the occasional individually-null row inside an otherwise good import.

## C. Production Movement needs one extra rule

This one is not a historical page — it computes day-over-day change, so a gated import can
poison a current comparison. If **either** side of a movement pair lacks type data, do not
compute the movement. Say which import is unusable and why. Do not silently substitute the next
import along, and do not report zero movement.

## D. Surface it in the import picker

Mark the 21 gated imports visibly wherever an import can be selected, so a user does not choose
one and land on an empty page with no explanation. Mark-level and weight-level views that do not
depend on Type or Status may keep working normally for these imports — only the
classification-dependent figures are withheld.

## WHAT NOT TO CHANGE

- Do NOT re-ingest, re-upload or re-process any source file.
- Do NOT modify `record_pool`. It is a current-state store; the historical state exists only in
  the source files and is not being recovered.
- Do NOT delete the COALESCE where `has_type_data` is true.
- Do NOT change bucket definitions, the parser, hashing, dedup, `copies` handling, ageing,
  activity classification, or the activity sets just consolidated into `lib/domain`.
- Do NOT show a fallback figure behind a toggle or a "best estimate" label. A fabricated figure
  with a caveat is still a fabricated figure.
- Do NOT touch the Project Wise MFC work, `loadLatestWipImport()`, the predecessor queries, or
  DC0 to DC15.
