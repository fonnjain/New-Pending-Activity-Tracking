TASK: Add a new bucket, "Pre Bucket B", that sits between Bucket A and Bucket B. It is a
STAGING GATE: a project cannot enter Bucket B until its colour and dates have been entered.

=====================================================================
THE FLOW
=====================================================================
    Bucket A            ->   Pre Bucket B              ->   Bucket B
    (no work order)          (qualifies for B, but          (colour + dates entered)
                              colour/dates NOT yet
                              supplied)

  - A project leaves Bucket A when it qualifies for Bucket B (work order raised / release
    progress appears / its marks appear in WIP). It lands in PRE BUCKET B, never straight
    into Bucket B.
  - It SITS in Pre Bucket B until the user supplies Colour, Date of Client MFC and Project
    Start Date (the existing MFC colour-coding entry form).
  - The moment that information exists, it moves into Bucket B automatically on the next
    render/import. No extra button, no manual "promote" action.

=====================================================================
THE GATE IS PER (PROJECT, MFC BATCH) PAIR — NOT PER PROJECT
=====================================================================
*** Each (project, MFC batch) pair must be coloured SEPARATELY to move. ***
A project with several batches moves piecemeal: its coloured pairs sit in Bucket B while its
uncoloured pairs remain in Pre Bucket B. This is intended, not a bug.

Gate condition for a pair:
    a colour assignment record exists for (normalized project, MFC batch)
      -> pair belongs to BUCKET B
    otherwise
      -> pair belongs to PRE BUCKET B

The colour record is the same one created by the MFC colour-coding feature (colour, Client MFC
date, Project Start date, keyed on project + MFC batch). Requiring the COLOUR is the gate;
treat a record as complete only if the colour AND both dates are present.

=====================================================================
WEIGHTS ARE EXCLUDED FROM BUCKET B WHILE IN PRE BUCKET B
=====================================================================
A pair sitting in Pre Bucket B contributes NOTHING to Bucket B — not its structures, not its
Release Balance, Fab, Galva or Yard, not its counts. Bucket B totals must reflect only
coloured pairs. There is no double presence: a pair is in exactly ONE of Pre Bucket B or
Bucket B, never both.

=====================================================================
PRE BUCKET B — behaviour and display
=====================================================================
- Same membership rule as Bucket B (Balance Release > 0, completed structures excluded), and
  the same measure columns (Release Balance, Fabrication, Galvanising, Yard), so the user sees
  exactly what is waiting to be released into B.
- Same Project -> MFC Batch grouping and the "Group by MFC" toggle as the other buckets.
- Show the MFC Batch column; a newly started project is typically all "Z" at first.
- Each row needs an obvious call to action, e.g. an "Assign colour" control that pre-fills the
  colour-coding form with that project and batch, so the user can clear the gate in one click.
- Show a clear count, e.g. "40 pairs awaiting colour assignment".
- Order the buckets in the UI as: A, Pre Bucket B, B, C, D, E.
- Include Pre Bucket B in the Excel export as its own sheet, same shape as the Bucket B sheet.
